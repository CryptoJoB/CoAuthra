Welcome to CoAuthra

A research collaboration explorer powered by OpenAlex, the free and open academic publication database.
Search any researcher by name or ORCID to instantly map their co-authorship universe.

🔍 Search

Type a researcher name or paste an ORCID iD and hit Search. In name search you can now tick multiple matches and load them together; ORCID mode also accepts multiple iDs separated by commas or spaces. CoAuthra fetches publications and builds a live network of collaborators — no account needed.

🖱 Interaction

Click any node to highlight it and all its connections.
Right-click a node to open the author's OpenAlex profile.
Drag nodes to reposition. Scroll to zoom.
Click the canvas background to deselect.

🎛 Filters

By default only the top ~100 strongest collaborations are shown to keep the graph readable — the threshold is set automatically. Adjust in the sidebar:

• Min. shared papers — lower to reveal more collaborators.
• Year range & Work type — narrow by year or publication type.
• Institution — show only co-authors from specific institutions.
• Topic clusters — filter by detected research community (on shared papers).
• Byline filter — show only papers where the searched author's listed affiliation matches their current institution, isolating collaborations built at a specific career stage.

All filters update stats, charts, and open access breakdown together.

🗺 Views

Network — co-author graph sized by shared papers.
Citations — nodes sized by co-author total citations.
Funders — funding agency connections (listed on publications).
Geo — world map of collaboration countries.
Affiliations — per-institution paper counts from each selected researcher's own bylines.

📡 Data Source

All publication and author data is fetched live from OpenAlex — a free and open academic publication database. When you search a researcher, CoAuthra calls the OpenAlex REST API to retrieve their full publication list using cursor-based pagination (200 papers per request), then enriches each co-author with citation counts, institutions, and geographic data via batched author lookups.

🕸 Network Construction

Each paper's authorship list is parsed to extract co-authors. A co-author's shared paper count is the number of papers they appear on alongside the searched researcher. Link strength is a fractional weight — each paper contributes 1 / (number of co-authors), so papers with fewer authors create stronger ties. Co-authors are ranked by shared count and the top ~100 are shown by default to keep the graph readable.

📐 Graph Layout

The network is rendered using D3.js force simulation with a custom layout pipeline. Nodes are pre-positioned into cluster sectors before the simulation begins — so research communities start physically close together — then refined by charge repulsion, link attraction, and a cluster cohesion force that continuously pulls same-topic nodes toward their group centroid. This avoids the random sprawl of a naive force layout and produces spatially meaningful clusters from the first frame.

🔬 Community Detection

Direct co-author-to-co-author edges (co-links) are computed from shared papers. The Louvain algorithm — a modularity-maximising community detection method — is run on this graph to assign cluster membership, grouping researchers who frequently collaborate with each other into the same colour cluster.

🎯 Assumptions & Definitions

Specific criteria worth knowing when interpreting the graph:

• Co-links are always-on direct connections between co-authors themselves — not just ties back to the searched researcher — shown as purple dashed lines and computed from shared papers. They form the edges that the Louvain community detection (see above) runs on to assign clusters. If a network has a lot of co-links, lower Max links shown in the sidebar — rendering too many at once can slow the graph down.

• Topic clusters reflect the primary topic of papers shared with the searched researcher — not that co-author's overall research focus across their whole career. A frequent collaborator's cluster can differ from what their own OpenAlex profile shows as their top topic.

• Citations (Citations view) size each node by that co-author's total lifetime citation count across all of their published work — not citations specific to papers shared with the searched researcher.

• Institution & Country use each co-author's last known (most recent) affiliation on record in OpenAlex — a single snapshot, not a full affiliation history. Co-authors OpenAlex can't resolve an institution for appear under "Unknown / None."

• Geo map counts a country's "Papers" as the number of distinct papers with at least one visible co-author affiliated there — a single paper with several co-authors from the same country still counts once, not once per co-author.

• Funders are pulled from OpenAlex's grants metadata (sourced via Crossref), which has inconsistent coverage across fields and eras. A paper showing no funder usually means that record is missing in OpenAlex, not that the work was unfunded.

• Link strength is fractional per paper (1 / number of co-authors), so a two-author paper creates a stronger tie than a fifty-author consortium paper with the same shared-paper count.

• Default filtering shows only the top ~100 strongest collaborations to keep the graph readable — lower Min. shared papers in the sidebar to reveal more.

🛠 Tech Stack

Visualisation: D3.js v7 + TopoJSON. Graph layout: custom D3 force simulation with sector seeding and cohesion forces. Community detection: Louvain (implemented in JavaScript). Geographic map: D3 natural-earth projection.
